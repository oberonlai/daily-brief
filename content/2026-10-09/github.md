## 非 WP

### 1. AI 一步一步呼叫工具太慢太貴 → 改成一次寫完整個任務程式、全部成功才生效 → 可一鍵復原的 MCP 中介層
- **來源**：[mcpdelta/mcpdelta](https://github.com/mcpdelta/mcpdelta)（★~79，10/8 新建；未標授權；App 尚未公開下載）— Delta MCP 夾在 AI 工具和你的 MCP 伺服器中間：AI 不再「讀、決定、呼叫一個工具、再讀」，而是把整件事寫成一小段程式；Delta 先檢查、用最少的呼叫執行、全部成功才套用，再把結果讀回確認；每個任務都記到 Activity，列出改動前後，可一鍵復原，不能復原的（例如已寄出的訊息）會先告訴你。官方實測 8 個情境，多步驟任務省 3.3–24.1 倍 token、成本低 1.4–8.1 倍。
- **標籤**：非 WP
- **為什麼值得做**：MCP 工具一多，token 和等待時間就爆；「全部成功才生效＋可復原」又剛好解決「不敢讓 agent 動正式資料」。這是 MCP 生態下一層的基礎設施，目前還沒有成熟的開源版本。
- **構想**：「MCP 操作紀錄與復原層」— 先針對單一服務（例如 WooCommerce 或 Notion）做：agent 的每次批次修改都留前後差異、可一鍵還原，月底給「AI 改了什麼」報告；Pro：團隊審核（大量改動要人按同意才套用）。
- **難度**：中高；切入：先追蹤它的 benchmark 頁和發布時間，拿自己最常用的一個 MCP 量一次「逐步呼叫」到底花多少 token。

### 2. 任何信箱 → 變成一條有順序、可重播的事件流 → agent 只能「提案」、你按同意才動信
- **來源**：[Kadri-cloud/email-engine](https://github.com/Kadri-cloud/email-engine)（★~6，10/6 新建；Apache-2.0）— 自架的信箱引擎：IMAP（含 IDLE 推送）、JMAP、轉寄進來的 SMTP 都能接，Gmail API 與 Microsoft Graph 實驗中；所有變化寫成可從任一游標重播的事件紀錄，可用輪詢、SSE 或 webhook 讀；動作會記錄、可復原（移動、標記、刪除、草稿）；可以設定 agent 只能「提案」，排進待審佇列；每個存取 token 限定帳號、資料夾與動作，還能把驗證碼、卡號、IBAN 遮掉；內建 MCP 伺服器與本機全文搜尋。0.1.0 beta。
- **標籤**：非 WP
- **為什麼值得做**：每個 AI 信件助理都在重做一樣的底層（同步、去重、復原、權限），而且最怕 AI 誤刪誤寄；把這一層做成「信件的 USB」，上面就能長出很多小產品。星數很低，適合當參考實作。
- **構想**：「AI 信件助理（只提案版）TW」— 接自己的信箱，AI 每天整理：哪些要回、帳單金額、釣魚警告，所有動作先排進待審清單，LINE 上按同意才執行；Pro：發票信自動抽出金額記帳、客服信自動分類到工單。
- **難度**：中；切入：先接一個測試信箱跑一週，看事件紀錄與復原是否穩定，再寫一個只會「標記 needs-reply」的小 agent。

### 3. 讓 coding agent 寫好自動化 → 直接部署成排程、webhook 或事件觸發 → Wix 出品的「程式碼版 Zapier」
- **來源**：[wix-incubator/whenever](https://github.com/wix-incubator/whenever)（★~18，10/7 新建；MIT；Wix 孵化）— Whenever 的 TypeScript SDK 與本機轉接器：用 agent 在本機寫工作流程（排程、webhook、事件、手動觸發），部署到 Whenever 後由平台代管憑證、重試與執行紀錄；agent 可以讀一份 `skill.md` 照著改寫並部署，或直接連它的遠端 MCP 伺服器，寫、測試、存成草稿等你發布。
- **標籤**：非 WP
- **為什麼值得做**：大公司開始把「agent 寫的程式」當成自動化的主角，而不是拖拉積木；這代表 Zapier／n8n 類產品的使用方式正在改變，「agent 寫、平台跑、人審核」會是新模式。
- **構想**：「agent 自動化範本包 TW」— 針對台灣常見流程（LINE 通知、綠界／藍新訂單、發票、Google Sheets 報表）做好可直接部署的工作流程範本與 skill；服務面：替小公司把手動流程改成每天自動跑；也可以在 WP 外掛裡提供「把站內事件送進這類平台」的 webhook。
- **難度**：低中；切入：先用它把一個自己每天手動做的小事（例如每日訂單彙整）部署成排程，記錄從寫到上線花多久。

### 4. ChatGPT 推出會生成介面的 Intelligent UI → 開源、任何模型都能用的版本 → 回答變成可拉滑桿的圖表與計算機
- **來源**：[0xcro3dile/answerui](https://github.com/0xcro3dile/answerui)（★~23，10/8 新建、10/9 仍在更新；MIT）— AnswerUI 用介面回答問題，而不是一大段文字：圖表、表單、計算機、可操作的 2D／3D 場景；拉動滑桿場景立即變化，算出的數字會回填到文字裡。模型以 OpenUI Lang 串流產生介面，每個場景在沙盒裡執行；支援任何 OpenAI 相容模型，也能用 Ollama 跑本機模型；`npx answerui-app` 或 Docker 一行啟動。
- **標籤**：非 WP
- **為什麼值得做**：昨天 OpenAI 才把 Intelligent UI 推給所有人，使用者很快會習慣「答案要能互動」；開源版讓你能把這種體驗放進自己的產品與客戶網站，不被綁在 ChatGPT 裡。
- **構想**：「互動式試算小工具產生器」— 給一段說明（例如房貸、保費、方案比較），自動產出可嵌入網頁的互動計算器與圖表；Pro：嵌進 WP 文章當區塊、記錄訪客輸入當名單線索。
- **難度**：中；切入：先拿它問 5 個你客戶常問的計算型問題，看產出的介面有幾個能直接放上網站。

### 5. 一人公司的收信、追客戶、開發票、做報表 → 交給一組在雲端電腦上工作的 AI 同事 → 隨時能看畫面、接手
- **來源**：[OrgoAI/bops](https://github.com/OrgoAI/bops)（★~219，10/6 新建、10/9 仍在更新；FSL-1.1-ALv2，兩年後轉 Apache-2.0；不得做成競品託管服務）— Mac App：一組 AI bot 負責收件匣、業務 pipeline、發票與報表，在你可以即時觀看、隨時接手的雲端電腦上做事；可以在 App、Slack、Telegram、Discord 找它們，Pro 以上還有專屬電話號碼與 email。方案 Free $0、Pro $20／月、Max $200／月，AI 用量按成本計；也可以自架。
- **標籤**：非 WP
- **為什麼值得做**：上線三天兩百多星、六十多個 fork，代表「AI 員工」從展示走向有定價的產品；它的方案設計（每個 bot 有自己的電腦、電話、信箱）很適合當你規劃自家 agent 服務時的對照。
- **構想**：「接案工作室 AI 營運助理 TW」— 專做台灣接案者的三件事：追未回覆的報價、到期提醒開發票、每週專案進度報告推 LINE；先不做通用平台，只做這三個流程做到好。
- **難度**：中；切入：先把它的 Plans 與 Roadmap 讀一遍，挑一個你自己每週都在做的營運工作，手動記錄一週花的時間，當作價值估算。

### 6. 產品上線要影片 → 不錄螢幕、不用 AI 生成糊掉的畫面 → 用你產品真實的畫面重建成短片
- **來源**：[display-dev/product-film](https://github.com/display-dev/product-film)（★~24，10/5 新建；MIT）— 給 Claude Code、Cursor、Codex 等用的 agent skill：從你產品的 HTML／CSS 或執行中 App 的 DOM 快照重建畫面，做成產品短片；四種路線（電影感主視覺、純產品、操作導覽、剪紙拼貼解說），一次出 16:9、9:16、4:5；附檢查腳本抓滑鼠停太久、單格閃爍等問題，重剪只要重渲染一段。
- **標籤**：非 WP
- **為什麼值得做**：每個 SaaS 與外掛上線都要影片，但錄螢幕很粗糙、外包很貴；「用真實 UI 做影片」畫面清楚又不會變形，而且規則寫得很細，是內容團隊可以直接用的流程。
- **構想**：「外掛／SaaS 上線影片代製 TW」— 客戶給網址或測試帳號，交付 30 秒上線影片＋三種比例社群版；Pro：每次版本更新自動重剪「本月新功能」短片；你自己的 WP 外掛也能先拿來做 WordPress.org 頁面的介紹影片。
- **難度**：低中；切入：先拿自己一個外掛的設定頁跑一支 walkthrough 影片，看要改多少才能用。

## WP

### 7. Automattic 推出 Spacefast → agent 做好的網站、報表、小工具一鍵發布成網址 → 背後是 WordPress 媒體庫
- **來源**：[spacefast/mcp](https://github.com/spacefast/mcp)（★~7，10/8 新建；MIT；Automattic 官方）— Spacefast 的遠端 MCP 伺服器設定與 MCP Registry 資料：在對話裡把網站、儀表板、報告或小工具直接發布成可分享的網址，可以繼續用聊天修改、設定誰能看、綁自己的網域、還原舊版本；未登入也能先發布，臨時空間保留約 33 小時，之後再認領。目前是研究預覽。同時期的 [f/f.camera](https://github.com/f/f.camera) 範例顯示，每個 Space 的內容與照片放在 WordPress 媒體庫，前端用 Spacefast Zero 執行。
- **標籤**：WP
- **為什麼值得做**：WordPress.com 的母公司直接做「agent 的發布層」，而且內容層還是 WordPress，這會改變一般人「做一個網站」的方式；外掛開發者要開始想：自己的功能怎麼讓 agent 在這種環境裡呼叫。
- **構想**：「Spacefast 版型與 skill 包」— 針對台灣常見需求（活動頁、報價單頁、作品集）做可直接發布的範本與對應 skill；開發面：觀察它怎麼用 WordPress 當內容後台，對照自家 WP Web MCP 外掛的設計。
- **難度**：低；切入：先加入候補、用 Claude Code 連上它的 MCP，發布一頁今天的早報看看體驗。

### 8. 上傳大圖後 WordPress 會偷偷保留超大原圖 → 列出來、打包下載、批次刪除 → 幫主機省空間
- **來源**：[Zodiac1978/list-original-uploads](https://github.com/Zodiac1978/list-original-uploads)（★~3，10/6 新建；GPL-2.0-or-later；作者為德國 WP 社群老手 Torsten Landsiedel）— 在「媒體」底下新增一頁，列出 WordPress 產生 `-scaled` 版本後仍保留、長或寬超過 2560 像素的原圖：預覽、檔名、尺寸、檔案大小、總共占多少空間；可打包成 ZIP 下載或批次刪除。只動 `original_image` 中繼資料指到的檔案，確定刪除成功才移除中繼資料。
- **標籤**：WP
- **為什麼值得做**：手機照片越來越大，攝影、電商、部落格站常有好幾 GB 是用不到的原圖，主機空間和備份費用都在浪費；這是很具體、站主一看就懂的痛點。
- **構想**：「媒體庫瘦身＋備份外掛」— 列出原圖之外，再加上未使用的圖片、重複檔案，刪除前自動備份到 Google Drive 或 S3；Pro：多站一起掃、每月寄「這個月省了多少空間」報告，可搭配代管方案一起賣。
- **難度**：低；切入：先在一個客戶的舊站裝起來，量一下原圖到底占了多少空間，當作銷售案例。
