GitHub 熱門 × WP／SaaS idea 早報｜2026-11-25

今天的 Trending 日榜、週榜仍是已報過或老牌專案，沒有入選。下面 8 則來自近幾天新建的高星 repo、近 3 天的 release，以及 Show HN。遊戲移植、外掛、破解、漏洞 PoC 與星數農場已排除。

1. AI 程式碼品味檢查：PR 的 slop 分數

  • GitHub：https://github.com/deterministic-machines/deslop-please（建立：2026-11-22）
  • 來源重點：MIT 的 Rust linter，主張深模組、窄介面，用來抓 AI 寫出來的鬆散程式碼。2026-11-24 發了 v0.1.4，約 737 星。
  • 為什麼值得做：團隊已經會掃 CVE，但沒人量「這份 AI 程式碼好不好維護」。
  • 產品構想：GitHub App 對每個 PR 打 slop 分數，留言指出過寬的介面與外洩的內部細節，並出週報給技術主管。
  • 難度與切入點：低中。先包現成 CLI，差異化做繁體中文說明與「可合併／先改」門檻。

2. 沒有 Mac 的 iOS Agent 測試雲

  • GitHub：https://github.com/Developing-Gamer/agent-sim（建立：2026-11-21）
  • 來源重點：在一般 Linux 上跑 iOS 模擬器給 AI agent 操作，不需要 Mac 或 GPU。建在 x86Sim 之上，2026-11-23 發了 v0.1.0，約 553 星。
  • 為什麼值得做：App 團隊想讓 agent 自己點過註冊與付款，但 Mac 農場又貴又難管。
  • 產品構想：上傳建置、選 iOS 版本，agent 用 API 看畫面、點擊，回傳可重播的失敗片段。按分鐘計費。
  • 難度與切入點：高。先做單一流程（登入→結帳）與錄影報告，賣給已經有 Android 測試、缺 iOS 的小團隊。

3. 測試守門的刪碼服務

  • GitHub：https://github.com/EL4CTEO/shrink-anything（建立：2026-11-23）
  • 來源重點：刪掉用不到的程式碼、檔案、相依與素材，每一刀都要用專案自己的測試守住。支援約 19 種語言，當天發了 v0.1.0，約 160 星。
  • 為什麼值得做：AI 生成的專案越長越大，人工刪碼又怕弄壞。
  • 產品構想：接上 CI，每個 PR 提案「可安全刪除」的 diff，通過測試才開 PR。按刪掉的行數或月費計價。
  • 難度與切入點：中。先做 TypeScript／PHP 專案，鎖定接了很多 AI 生成外掛的工作室。

4. 給 Agent 用的 Postgres 分析讀副本

  • GitHub：https://github.com/embeddable-hq/mason-data（建立：2026-10-27）
  • 來源重點：Show HN（2026-11-24，約 80 分）。單一行程把 Postgres 同步進欄位式引擎，查詢語法仍是 Postgres，並給每個 agent 獨立帳號、欄位與列權限，內建 MCP。官網已有 Mason Cloud。
  • 為什麼值得做：把正式庫直接交給 agent 查報表，既慢又有洩漏風險。
  • 產品構想：託管「分析讀副本」：選表、設 agent 角色、看每條 SQL 日誌。賣給已有 Postgres 的 SaaS，而不是再做一個 BI。
  • 難度與切入點：中高。不要跟官方雲硬碰。先做「代理商版」：多客戶、用量上限、查詢被拒時的中文修法提示。

5. 用閒置電腦訓練自己的小模型

  • GitHub：https://github.com/sous-labs/songe（建立：2026-11-20）
  • 來源重點：用閒置算力訓練本機模型的引擎，Apache-2.0，官網 souslabs.ai/songe，約 658 星，仍在每天更新。
  • 為什麼值得做：中小團隊想要自己的小模型，但買 GPU 或長租雲端都划不來。

  • 難度與切入點：高。先做單機「下班後訓練」與進度通知，再做多機佇列。

  • GitHub：https://github.com/mahbubur001/releasedock（建立：2026-11-22）
  • 來源重點：macOS 原生 App，把 ZIP 或原始碼資料夾檢查、預覽、提交到 WordPress.org SVN，並在提交後驗證。2026-11-24 發了 v0.2.2，README 寫有 210 個測試。星數仍少。

  • 難度與切入點：中。先做檢查與預覽，不先做自動提交；鎖定已有 svn 帳號的外掛作者。
