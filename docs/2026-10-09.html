GitHub 熱門 × 產品點子

GitHub Idea 早報 · 2026-10-09（台北）

訊號：GitHub Trending（日／週）＋ Search（10/4 後新建高星／MCP／agent／self-hosted／自動化／SaaS／WordPress／WooCommerce）。Trending 今天幾乎都是前幾天報過的面孔，新東西主要來自搜尋；搜尋結果裡有一大批同日建立、星數相同、名稱是「某某 SaaS-download」的可疑 repo，以及大量帳號批量註冊工具，全部排除。非 WP 為主；今日焦點是「讓 AI 一次寫完整個任務、還能復原的 MCP 中介層」、「把信箱變成 agent 能安全操作的事件流」、「agent 寫好的自動化直接部署成排程」、「回答變成可以拉滑桿的介面」、「一人公司的 AI 營運團隊」、「用真實產品畫面做產品影片」，WP 側跟進「Automattic 新推的 Spacefast」與「清掉 WP 偷偷保留的超大原圖」。

非 WP

1. AI 一步一步呼叫工具太慢太貴 → 改成一次寫完整個任務程式、全部成功才生效 → 可一鍵復原的 MCP 中介層

  • 來源：mcpdelta/mcpdelta（★~79，10/8 新建；未標授權；App 尚未公開下載）— Delta MCP 夾在 AI 工具和你的 MCP 伺服器中間：AI 不再「讀、決定、呼叫一個工具、再讀」，而是把整件事寫成一小段程式；Delta 先檢查、用最少的呼叫執行、全部成功才套用，再把結果讀回確認；每個任務都記到 Activity，列出改動前後，可一鍵復原，不能復原的（例如已寄出的訊息）會先告訴你。官方實測 8 個情境，多步驟任務省 3.3–24.1 倍 token、成本低 1.4–8.1 倍。
  • 標籤：非 WP
  • 為什麼值得做：MCP 工具一多，token 和等待時間就爆；「全部成功才生效＋可復原」又剛好解決「不敢讓 agent 動正式資料」。這是 MCP 生態下一層的基礎設施，目前還沒有成熟的開源版本。
  • 構想：「MCP 操作紀錄與復原層」— 先針對單一服務（例如 WooCommerce 或 Notion）做：agent 的每次批次修改都留前後差異、可一鍵還原，月底給「AI 改了什麼」報告；Pro：團隊審核（大量改動要人按同意才套用）。
  • 難度：中高；切入：先追蹤它的 benchmark 頁和發布時間，拿自己最常用的一個 MCP 量一次「逐步呼叫」到底花多少 token。

2. 任何信箱 → 變成一條有順序、可重播的事件流 → agent 只能「提案」、你按同意才動信

  • 來源：Kadri-cloud/email-engine（★~6，10/6 新建；Apache-2.0）— 自架的信箱引擎：IMAP（含 IDLE 推送）、JMAP、轉寄進來的 SMTP 都能接，Gmail API 與 Microsoft Graph 實驗中；所有變化寫成可從任一游標重播的事件紀錄，可用輪詢、SSE 或 webhook 讀；動作會記錄、可復原（移動、標記、刪除、草稿）；可以設定 agent 只能「提案」，排進待審佇列；每個存取 token 限定帳號、資料夾與動作，還能把驗證碼、卡號、IBAN 遮掉；內建 MCP 伺服器與本機全文搜尋。0.1.0 beta。
  • 標籤：非 WP
  • 為什麼值得做：每個 AI 信件助理都在重做一樣的底層（同步、去重、復原、權限），而且最怕 AI 誤刪誤寄；把這一層做成「信件的 USB」，上面就能長出很多小產品。星數很低，適合當參考實作。
  • 構想：「AI 信件助理（只提案版）TW」— 接自己的信箱，AI 每天整理：哪些要回、帳單金額、釣魚警告，所有動作先排進待審清單，LINE 上按同意才執行；Pro：發票信自動抽出金額記帳、客服信自動分類到工單。
  • 難度：中；切入：先接一個測試信箱跑一週，看事件紀錄與復原是否穩定，再寫一個只會「標記 needs-reply」的小 agent。

3. 讓 coding agent 寫好自動化 → 直接部署成排程、webhook 或事件觸發 → Wix 出品的「程式碼版 Zapier」
