GitHub 熱門 × 產品點子

GitHub Idea 早報 · 2026-10-08（台北）

訊號：GitHub Trending（日／週）＋ Search（10/1 後新建高星／自架錯誤追蹤／推送前 AI 審碼／電商比價 MCP／播客轉文章／教材轉講義／創業驗證 skill／WooCommerce × ChatGPT 廣告／WP MCP）。今天 Trending 大多是前幾天報過的老面孔，新東西主要來自搜尋。非 WP 為主；今日焦點是「換一個網址就搬離 Sentry」、「push 前讓另一個 agent 審你的改動」、「讓 agent 幫你比價看歷史價」、「逐字稿變成能發的長文」、「投影片變成 iPad 講義」、「開店前先讓 100 個模擬買家投票」，WP 側跟進「ChatGPT 廣告的轉換追蹤」與「每一步都能復原的 WP MCP」。

非 WP

1. 不改 SDK、只換 DSN → 錯誤回報送到自己的伺服器 → 自架版 Sentry

  • 來源：olucurious/watchtower（★~17，10/3 新建；Apache-2.0）— 自架錯誤追蹤：直接吃 Sentry 各語言 SDK 和 AppSignal agent 的回報格式，搬家只要改 DSN 或回報網址；錯誤依成因分組、已解決的再發生會自動重開；錯誤暴增時每個 issue 每小時超過 20 筆只抽樣存，不會塞爆硬碟；通知到 Slack、Linear、Email；內建 MCP 讓 Claude Code、Codex、Cursor 拿到完整的錯誤說明與原始碼脈絡；存之前先遮掉卡號、token 等敏感字串。單一 Go 執行檔加 Postgres。
  • 標籤：非 WP
  • 為什麼值得做：Sentry 隨事件量計價，小團隊和接案公司常被帳單嚇到，有資料落地要求的客戶又不能用雲端版；「SDK 不動就能搬」把搬家成本降到幾乎為零。MCP 那段讓「錯誤 → agent 修」變成一條線，是好賣點。星數還低，適合當參考實作。
  • 構想：「代管錯誤追蹤 TW」— 替代管客戶架一套，所有網站與 App 的錯誤集中、推 LINE，每週寄「本週前 5 大錯誤與是否已修」報告；Pro：agent 依錯誤自動開 PR 草稿；可和昨天的心跳監控（uptimy）綁成一個維運方案。
  • 難度：低中；切入：先把自己一個專案的 Sentry DSN 指過去跑兩週，比較分組品質和 Sentry 差多少。

2. 還沒 push 前 → 掃描工具只看你改的那幾行 → 再派另一個 agent 逐條複核

  • 來源：openqodex/openqodex（★~209，10/2 新建、10/7 仍在更新；Apache-2.0）— 給 Claude Code 與 Codex 用的開源審碼：openqodex review 抓出尚未 push 的 commit 和未提交的改動，跑對應的靜態掃描、密鑰外洩、相依套件與 lint，只留落在你改動行上的問題；接著另開一個 Claude Code 或 Codex 程序讀凍結的改動副本，逐條確認掃描結果並看過每一行改動，最後用腳本檢查它的回答，輸出 report.md、report.json、report.sarif。不需要額外 API key 或伺服器；也能審指定分支或 PR。
  • 標籤：非 WP
  • 為什麼值得做：agent 寫程式越來越快，瓶頸變成「誰來審」；用「寫的 agent」以外的另一個程序審、再用腳本核對，比讓同一個 agent 自己說沒問題可信得多。只審改動行也讓雜訊少、願意天天用。
  • 構想：「團隊 AI 審碼規則包 TW」— 在 OpenQodex 上面加各團隊自己的規則（WP 編碼規範、PHP 安全檢查、台灣個資欄位不得寫 log），每個 PR 自動附報告；Pro：每月「最常被抓到的問題」統計，當新人教材。
  • 難度：低；切入：先在自己的一個 WP 外掛 repo 跑一週，記錄抓到幾個真問題、幾個誤報。

3. 「這台現在最便宜是哪家？是不是好時機買？」→ 一個唯讀的電商比價 MCP

  • 來源：sepehr071/digikala-mcp（★~25，10/3 新建；MIT）— 伊朗最大電商 Digikala 的非官方唯讀 MCP：搜尋商品、比較同一商品所有賣家的報價、查價格歷史、讀評價與問答、看當日特價；README 示範 agent 三次呼叫就答出「最便宜的是哪個規格、哪個賣家，以及跟昨天和本月最低價比是不是好價」。已上 MCP Registry，可一鍵裝進 Cursor 和 VS Code。
  • 標籤：非 WP
  • 為什麼值得做：同一支手機在電商上有多種規格、多個賣家，價格天天變，人工比價很花時間；「比價＋歷史價」是 agent 購物最實用的場景。台灣也有一樣的痛點，而且還沒看到好用的繁中版本。要留意各平台的使用條款與抓取頻率。
  • 構想：「台灣比價 MCP」— 先做一個平台的唯讀查詢（搜尋、多賣家比價、自建價格歷史），讓 agent 回答「現在買划不划算」；Pro：降價到目標價推 LINE、每週關注清單價格變動報告；B2B 版：品牌商監看經銷商有沒有破價。
  • 難度：中；切入：先挑 20 個常買的 3C 商品每天記一次價，跑兩週就有歷史價資料可以示範。

4. 多人對談逐字稿 → 從「誰說了什麼」改成「依話題組織」→ 能直接發的長文

  • 來源：orange2ai/podcast-to-article（★~61，10/7 新建；MIT；簡中）— 把播客逐字稿整理成可發布長文的 Agent Skill：把以發言人和時間為主軸的逐字稿，改成以話題和判斷為主軸；校正人名、砍掉約三分之一篇幅、保留原話語氣，並附自檢腳本 check_style.py 抓破折號、對仗句、總結腔等 AI 味寫法。README 實測一份 5730 字的稿整理成 3703 字。
  • 標籤：非 WP
