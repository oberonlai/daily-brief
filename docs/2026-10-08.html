GitHub 熱門 × 產品點子

GitHub Idea 早報 · 2026-10-08（台北）

訊號：GitHub Trending（日／週）＋ Search（10/1 後新建高星／自架錯誤追蹤／推送前 AI 審碼／電商比價 MCP／播客轉文章／教材轉講義／創業驗證 skill／WooCommerce × ChatGPT 廣告／WP MCP）。今天 Trending 大多是前幾天報過的老面孔，新東西主要來自搜尋。非 WP 為主；今日焦點是「換一個網址就搬離 Sentry」、「push 前讓另一個 agent 審你的改動」、「讓 agent 幫你比價看歷史價」、「逐字稿變成能發的長文」、「投影片變成 iPad 講義」、「開店前先讓 100 個模擬買家投票」，WP 側跟進「ChatGPT 廣告的轉換追蹤」與「每一步都能復原的 WP MCP」。

非 WP

1. 不改 SDK、只換 DSN → 錯誤回報送到自己的伺服器 → 自架版 Sentry

  • 來源：olucurious/watchtower（★~17，10/3 新建；Apache-2.0）— 自架錯誤追蹤：直接吃 Sentry 各語言 SDK 和 AppSignal agent 的回報格式，搬家只要改 DSN 或回報網址；錯誤依成因分組、已解決的再發生會自動重開；錯誤暴增時每個 issue 每小時超過 20 筆只抽樣存，不會塞爆硬碟；通知到 Slack、Linear、Email；內建 MCP 讓 Claude Code、Codex、Cursor 拿到完整的錯誤說明與原始碼脈絡；存之前先遮掉卡號、token 等敏感字串。單一 Go 執行檔加 Postgres。
  • 標籤：非 WP
  • 為什麼值得做：Sentry 隨事件量計價，小團隊和接案公司常被帳單嚇到，有資料落地要求的客戶又不能用雲端版；「SDK 不動就能搬」把搬家成本降到幾乎為零。MCP 那段讓「錯誤 → agent 修」變成一條線，是好賣點。星數還低，適合當參考實作。
  • 構想：「代管錯誤追蹤 TW」— 替代管客戶架一套，所有網站與 App 的錯誤集中、推 LINE，每週寄「本週前 5 大錯誤與是否已修」報告；Pro：agent 依錯誤自動開 PR 草稿；可和昨天的心跳監控（uptimy）綁成一個維運方案。
  • 難度：低中；切入：先把自己一個專案的 Sentry DSN 指過去跑兩週，比較分組品質和 Sentry 差多少。

2. 還沒 push 前 → 掃描工具只看你改的那幾行 → 再派另一個 agent 逐條複核

  • 來源：openqodex/openqodex（★~209，10/2 新建、10/7 仍在更新；Apache-2.0）— 給 Claude Code 與 Codex 用的開源審碼：openqodex review 抓出尚未 push 的 commit 和未提交的改動，跑對應的靜態掃描、密鑰外洩、相依套件與 lint，只留落在你改動行上的問題；接著另開一個 Claude Code 或 Codex 程序讀凍結的改動副本，逐條確認掃描結果並看過每一行改動，最後用腳本檢查它的回答，輸出 report.md、report.json、report.sarif。不需要額外 API key 或伺服器；也能審指定分支或 PR。
  • 標籤：非 WP
  • 為什麼值得做：agent 寫程式越來越快，瓶頸變成「誰來審」；用「寫的 agent」以外的另一個程序審、再用腳本核對，比讓同一個 agent 自己說沒問題可信得多。只審改動行也讓雜訊少、願意天天用。
  • 構想：「團隊 AI 審碼規則包 TW」— 在 OpenQodex 上面加各團隊自己的規則（WP 編碼規範、PHP 安全檢查、台灣個資欄位不得寫 log），每個 PR 自動附報告；Pro：每月「最常被抓到的問題」統計，當新人教材。
  • 難度：低；切入：先在自己的一個 WP 外掛 repo 跑一週，記錄抓到幾個真問題、幾個誤報。

3. 「這台現在最便宜是哪家？是不是好時機買？」→ 一個唯讀的電商比價 MCP

  • 來源：sepehr071/digikala-mcp（★~25，10/3 新建；MIT）— 伊朗最大電商 Digikala 的非官方唯讀 MCP：搜尋商品、比較同一商品所有賣家的報價、查價格歷史、讀評價與問答、看當日特價；README 示範 agent 三次呼叫就答出「最便宜的是哪個規格、哪個賣家，以及跟昨天和本月最低價比是不是好價」。已上 MCP Registry，可一鍵裝進 Cursor 和 VS Code。
  • 標籤：非 WP
  • 為什麼值得做：同一支手機在電商上有多種規格、多個賣家，價格天天變，人工比價很花時間；「比價＋歷史價」是 agent 購物最實用的場景。台灣也有一樣的痛點，而且還沒看到好用的繁中版本。要留意各平台的使用條款與抓取頻率。
  • 構想：「台灣比價 MCP」— 先做一個平台的唯讀查詢（搜尋、多賣家比價、自建價格歷史），讓 agent 回答「現在買划不划算」；Pro：降價到目標價推 LINE、每週關注清單價格變動報告；B2B 版：品牌商監看經銷商有沒有破價。
  • 難度：中；切入：先挑 20 個常買的 3C 商品每天記一次價，跑兩週就有歷史價資料可以示範。

4. 多人對談逐字稿 → 從「誰說了什麼」改成「依話題組織」→ 能直接發的長文

  • 來源：orange2ai/podcast-to-article（★~61，10/7 新建；MIT；簡中）— 把播客逐字稿整理成可發布長文的 Agent Skill：把以發言人和時間為主軸的逐字稿，改成以話題和判斷為主軸；校正人名、砍掉約三分之一篇幅、保留原話語氣，並附自檢腳本 check_style.py 抓破折號、對仗句、總結腔等 AI 味寫法。README 實測一份 5730 字的稿整理成 3703 字。
  • 標籤：非 WP
  • 為什麼值得做：直接叫模型「把逐字稿寫成文章」通常變成會議紀錄或空話；這個 skill 把編輯的判斷寫成規則和檢查腳本，正是內容團隊最缺的。播客、直播、線上講座都有同樣需求。
  • 構想：「講座／播客轉文章服務 TW」— 上傳錄音，產出繁中逐字稿、一篇長文、3 則社群貼文與 SEO 標題；Pro：學你的文風、一鍵發到 WP 草稿；可接到人味潤稿外掛的去 AI 味檢查。
  • 難度：低；切入：先拿自己或朋友的一集播客跑一次，把成品和人工編輯版對照，找出繁中需要改的規則。

5. 老師的投影片或 PDF → AI 先讀懂再重新教一次 → iPad 尺寸、可手寫作答的深色講義

  • 來源：xamjiang/handout-remake（★~92，10/6 新建；MIT；繁中）— 「深色講義」Agent Skill：把上課投影片、PDF 或筆記交給 AI，依「生活情境、白話定義、圖解、公式、例題」的順序從零重講，術語附英文；頁面就是 11 吋 iPad 直向尺寸、深色底；練習題附書寫區，解答放下一頁；建置時自動檢查有沒有內容超出版面，例題數字用程式重算；輸出全向量 PDF。作者已在 Claude Cowork 與 Claude.ai 實測。
  • 標籤：非 WP
  • 為什麼值得做：學生最常抱怨投影片「步驟都省略了」；這個 skill 不只排版，而是把內容重新教一遍，還核對數字，剛好接得上備課與補教市場。作者本身是台灣、輸出就是繁中，生態很近。
  • 構想：「備課講義產生器」— 老師上傳一份教材，產出學生版講義、教師版（含解答與教學提示）和一份小考；Pro：依班級程度調整難度、匯出 GoodNotes 可用格式；可直接放進備課天堂當一個付費功能。
  • 難度：低中；切入：先拿一份國高中數學或理化投影片跑一次，請一位老師看哪些地方要改。

6. 開店前先讓「董事會」打分、100 個模擬買家投票 → 創業點子驗證套件

  • 來源：Jakeschincariol/founder-skill（★~63，10/7 新建；MIT）— 11 個免費 Claude skill，在你花錢之前測試一門生意：董事會（三個子 agent 分別用《$100M Offers》、《從 0 到 1》、賈伯斯傳的框架評分並投票）、競品調查（直接與間接競品、價格、客人抱怨，每項附連結）、模擬消費者（預設 100 個不同收入與習慣的買家 agent，統計誰會買、為什麼不買）、定價、行銷、營運與計畫；可裝成 Claude Code 外掛，工具只需要 Python。
  • 標籤：非 WP
  • 為什麼值得做：模擬買家不能取代真實訪談，但能在一小時內把「顯然不成立」的點子刷掉，並逼你寫清楚目標客群與定價；這套流程很適合包成給接案客戶或創業課學員的服務。
  • 構想：「點子健檢報告 TW」— 輸入點子與目標客群，產出繁中報告：台灣競品表、定價建議、模擬買家的主要反對理由，以及 3 個最便宜的真實驗證方法（LINE 社群問卷、Landing page、預購）；Pro：加上一頁式網站草稿直接上 WP。
  • 難度：低；切入：先拿這份早報裡的 3 個點子跑一次，看模擬結果和你自己的判斷差多少。

WP

7. WooCommerce 瀏覽、加購、結帳、購買 → 回報給 ChatGPT 廣告 → 量 ChatGPT 帶來多少訂單

  • 來源：besthand/pixel-for-openai-ads（★~3，10/3 新建、10/7 仍在更新；GPL-2.0；繁中介面，作者為「硬是要學」的手哥）— WooCommerce 外掛：依 OpenAI 官方 Measurement Pixel 文件，把商品瀏覽、加入購物車、開始結帳、完成購買、註冊回報給 ChatGPT Ads；可選擇加上伺服器端 Conversions API，與瀏覽器事件共用事件 ID 去重；支援 WordPress Consent API 依訪客同意控制追蹤；有最近 40 筆伺服器傳送紀錄可查；還能產生、驗證商品目錄 CSV，或用 Advertiser API 以 SFTP 定期同步。
  • 標籤：WP
  • 為什麼值得做：ChatGPT 開始有廣告，店家第一個問題就是「到底有沒有帶來訂單」；這是很早期、很新的追蹤需求，台灣已經有人做出繁中版，代表市場會很快動起來。
  • 構想：「AI 廣告與 AI 推薦成效儀表 TW」— 把 ChatGPT 廣告的轉換、來自 AI 的自然流量（搭配前幾天的 AI 推薦能見度與 llms.txt）放在同一份月報；服務面：替店家設定像素、商品目錄與同意橫幅。可以先和作者交流，而不是另做一個一樣的外掛。
  • 難度：低中；切入：先在一個測試 WooCommerce 站裝起來，把事件送出與去重跑通，整理成一篇設定教學。

8. 讓 AI 改你的 WP 網站 → 每一步都有存檔點、可以一鍵復原 → 敢在正式站上用的 MCP

  • 來源：februality/cowboy-mcp（★~10，10/7 仍在更新、v1.7.1；GPL-2.0；已上 WordPress.org）— 把 WordPress 變成 MCP 伺服器的外掛：最多 203 個內建工具，再加上其他外掛透過 WordPress Abilities API 註冊的能力（內容、區塊編輯器、WooCommerce、選單、外掛佈景、SEO 外掛、ACF、Elementor 等）；每次改動都記下改動前的狀態、可單筆或批次復原，另有資料庫存檔點與稽核紀錄；外掛更新前先備份，健康檢查失敗就自動還原；預設安全模式（破壞性操作要確認）、每個寫入工具都能試跑、金鑰可設唯讀與速率限制。端點跑在你自己的 WP 裡，不經第三方中繼。
  • 標籤：WP
  • 為什麼值得做：站主不敢讓 AI 碰正式站，最大原因是「改壞了回不去」；「每一步可復原＋稽核紀錄」正好回答這個顧慮。對正在做 WP Web MCP 外掛的你，它的復原與權限設計是很好的對照組。
  • 構想：「AI 網站管家代管方案 TW」— 客戶用 LINE 說要改什麼，agent 透過這類 MCP 在試跑模式先做、截圖給客戶確認，再正式套用，月底附「本月 AI 幫你改了哪些、哪些被復原」報告；開發面：把復原日誌與試跑的設計吸收進自家 WP Web MCP 外掛。
  • 難度：中；切入：先在測試站裝 Cowboy MCP，讓 Claude Code 做 10 件常見維護工作，記錄哪些需要復原、復原是否乾淨。
